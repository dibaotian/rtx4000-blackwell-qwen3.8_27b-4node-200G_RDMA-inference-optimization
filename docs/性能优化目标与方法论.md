# /goal — 4-Node RTX PRO 4000 Blackwell Qwen3.8-27B 推理性能优化

## 1. 项目目标

在 4 台独立服务器上，每台使用 1 × RTX PRO 4000 Blackwell 24GB，通过 200G RDMA 互联，建立 Qwen3.8-27B 高性能推理环境。

硬件拓扑：

```text
Node0                         Node1
RTX PRO 4000 24GB             RTX PRO 4000 24GB
     │                              │
     └────────── 200G RDMA ─────────┘

Node2                         Node3
RTX PRO 4000 24GB             RTX PRO 4000 24GB
     │                              │
     └────────── 200G RDMA ─────────┘
```

最终需要确定：

1. 最适合 RTX PRO 4000 Blackwell 24GB 的 Qwen3.8-27B 量化模型。
2. 最佳 inference runtime。
3. 最佳量化格式。
4. 最佳 MTP 配置。
5. 单 GPU 最佳性能。
6. 4-node DP=4 最佳 aggregate throughput。
7. TP=4 与 DP=4 的性能差异。
8. 200G RDMA 在 TP 模式下的通信开销。
9. 性能瓶颈究竟来自：
   - GPU compute
   - GPU memory bandwidth
   - KV cache
   - attention
   - MTP
   - CPU
   - PCIe
   - RDMA
   - NCCL/distributed communication
   - runtime scheduling

---

# 2. 最终优化原则

本项目不是单纯寻找一个“能跑”的配置。

必须采用：

```text
Baseline
   ↓
Measure
   ↓
Analyze bottleneck
   ↓
Change ONE important variable
   ↓
Measure again
   ↓
Compare
   ↓
Keep / Reject
   ↓
下一轮优化
```

禁止一次修改多个关键变量后无法判断性能变化来源。

例如：

错误：

```text
NVFP4
+ MTP3
+ FP8 KV
+ CUDA Graph
+ batch=4
```

一次全部修改，然后无法判断是哪一个因素带来的提升。

正确：

```text
NVFP4 baseline
      ↓
NVFP4 + MTP1
      ↓
NVFP4 + MTP2
      ↓
NVFP4 + MTP3
      ↓
最佳 MTP
      ↓
再测试 KV cache
```

# 4. 性能指标定义

所有 benchmark 必须至少记录以下指标。

## 4.1 Throughput

### Output throughput

```text
output_tokens_per_second
```

定义：

```text
所有请求实际生成的 output tokens
/
benchmark 实际运行时间
```

### Aggregate throughput

对于 4-node DP：

```text
aggregate output tok/s
=
Node0 output tok/s
+
Node1 output tok/s
+
Node2 output tok/s
+
Node3 output tok/s
```

不能把单请求 tok/s 和 aggregate tok/s 混淆。

---

# 5. Latency 指标

记录：

```text
TTFT
TPOT
ITL
E2E latency
```

其中：

### TTFT

Time To First Token。

重点观察：

```text
prefill performance
```

### TPOT

Time Per Output Token。

计算：

```text
TPOT = decode latency / generated tokens
```

因此：

```text
decode tok/s = 1 / TPOT
```

近似关系：

```text
50 tok/s
≈
20 ms/token
```


# 9. 性能有效性判断

如果两次测试：

```text
difference < 3%
```

认为：

```text
性能基本相同
```

如果：

```text
3% ~ 5%
```

认为：

```text
轻微变化
```

如果：

```text
5% ~ 10%
```

认为：

```text
有意义的性能变化
```

如果：

```text
> 10%
```

认为：

```text
明显性能变化
```

所有优化结论必须基于至少 3 次有效测试。

## 12.1 MTP 分析

对于每个 MTP configuration，记录：

```text

TPOT
accepted tokens
acceptance rate
GPU utilization
GPU memory
```

计算：

```text
MTP speedup =
MTP tok/s / baseline tok/s
```

例如：

```text
baseline = 45 tok/s
MTP3 = 60 tok/s

speedup = 60 / 45
        = 1.33
        = +33%
```

## 12.2 MTP 选择原则

```text

```

```text

MTP2 = 60 tok/s
```


# 19. DP Scaling 分析

单 GPU：

```text
S1
```

4 GPU：

```text
S4
```

理论：

```text
Ideal = S1 × 4
```

实际：

```text
S4
```

计算：

```text
Scaling efficiency =
S4 / (S1 × 4)
```

例如：

```text
S1 = 55 tok/s
Ideal = 220 tok/s
Actual = 205 tok/s

Efficiency =
205 / 220
= 93.2%
```

目标：

```text
>85%   acceptable
>90%   good
>95%   excellent
```

---

# 20. DP=4 异常分析

如果：

```text
S4 < 0.85 × S1 × 4
```

必须进入诊断流程。

依次检查：

### 1. Request scheduling

确认请求是否均匀分配到：

```text
Node0
Node1
Node2
Node3
```

### 2. GPU utilization

检查是否某个节点：

```text
GPU utilization = 95%
```

而其他节点：

```text
GPU utilization = 40%
```

如果存在：

```text
load imbalance
```

优化 request scheduler。

### 3. 网络

确认 DP 模式是否产生异常 RDMA traffic。

如果没有：

```text
RDMA不是主要瓶颈
```

### 4. CPU

检查：

```text
CPU utilization
NUMA
PCIe
```
